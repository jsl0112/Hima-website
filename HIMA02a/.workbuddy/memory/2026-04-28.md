## 经验（续 2）

- **坐标系陷阱**：Figma `get_node` 返回的子节点 bounds 是 **画布绝对坐标**，不是相对父容器，前端直接用这些坐标贴到 `position:absolute` 就行，**不要做 `child.x - parent.x` 这种错误减法**。

## 第六轮迭代：漩涡固定/icon hover 定住浮动/Stats 并入 Hero/Ticker 去白底/副标题不换行

用户贴出的设计稿截图还原缺失点，5 条集中修：

- **漩涡固定正中心**：上一版 `vortexIn` 从 scale(1.8) → scale(1) 的过程让漩涡"缩回来"给人位移错觉。这版改成 `vortexIn` 只做"从 .6 放大到 1"的入场（纯 scale，不改 translate），入场后衔接 `vortexLoop` 无限循环——只做呼吸缩放 `scale(1 ↔ 1.08)` + 自转 `rotate(0 → 360deg)`，`translate(-50%,-50%)` 恒定锁死中心点。这样漩涡永远卡在画面正中心，只是不停地"收缩放大 + 慢转"，不再飘来飘去。
- **Icon hover "定住 + 微动态"**：单纯给 hover 加 `transform: scale(1.1)` 会覆盖 `animation` 的 transform，导致浮动停止。解法是**用 hover 替换整个 animation**——默认跑 `iconFloat`（translateY ±10px），hover 切换到 `iconFloatHover`（基线 scale 1.12 ~ 1.14，叠加 translateY -2 ~ -6px、微旋转），这样 hover 本身就是一个"更高基线 + 更细浮动"的 keyframe。用户观感就是"鼠标一悬停图标定住放大，但它仍在微微浮动"。
- **Stats 区搬到 Hero 内**：之前 Stats 是独立 `<section>` 放在 Hero 下面，违反了设计稿——设计稿里 Stats 就在 Hero 底部、Logo Ticker 正上方，同属首屏。把整块移入 `.hero-canvas` 变成 `<div class="hero-stats" style="left:0;top:620px;width:1920px">`，这样它会跟着 Hero 的 `scale(100vw/1920)` 一起等比缩放，坐标锁死不会漂。独立 `.stats`/`.stats-inner` 样式清理掉，新建 `.hero-stats .stat-*` 一套更紧凑的尺寸（num 72px / title 24px / desc 12px）以适配画布内空间。
- **Logo Ticker 去白底**：设计稿里 Ticker 没有毛玻璃白底，直接贴在 Hero 浅蓝渐变上。把 `background: rgba(255,255,255,.6) + backdrop-filter: blur` 改成 `background: transparent`，两侧渐变遮罩颜色从白色改成 Hero 底部的浅蓝 `#dce8ff`（这样淡出效果跟背景融合）。同时隐藏 `.ticker-label`（设计稿里只有图标没有文字标签），让 Ticker 变成纯"12 个图标 + chzzk/Mirrativ 两个文字 logo"的排布。
- **副标题强制不换行**：给 `.hero-subtitle` 加 `white-space: nowrap`，同时把固定的 `width:528px` 删掉（改为 `width:auto`）。36 个汉字 × 16px ≈ 600px，从 x=560 出发到约 x=1160，在 1920 画布里留足空间，不会越界。

经验新增：

- **CSS `animation` + `:hover transform` 冲突**：hover 加 transform 会把正在跑的 animation 覆盖，动画等于被"停住"。**正解是给 hover 替换另一套 animation（更贴近目标状态的 keyframes）**，而不是硬覆盖 transform。这样既保留了"还在动"的感觉，又实现了"被鼠标抓住放大"的视觉效果。
- **固定位置元素的"呼吸动画"要显式锁 translate**：在 `@keyframes` 里每一帧都必须写完整的 `translate(-50%, -50%)`，不能偷懒只写 `scale` 或 `rotate`，否则 transform 会丢掉 translate 回到左上角造成"闪烁漂移"。
- **1920 画布内嵌子模块 vs 画布外独立 section**：当设计稿里多个区块属于"同一屏"时（比如 Hero + Stats + Ticker 合起来 1006px 高），最好统一放到同一个 `.hero-canvas` 里跟随 scale 缩放，而不是拆成多个 `<section>` 各自响应式。后者会因为缩放比例不一致出现"电脑屏幕越宽 Stats 越跟 Hero 对不齐"的问题。
- **设计稿截图是最终判断依据**：Figma 节点数据给出来的位置/尺寸未必跟设计稿视觉一致（尤其是 Ticker 位置和 Stats 是否在 Hero 内），一定要用截图交叉验证，不能只信 Figma API。

## 第七轮迭代：漩涡真·锁死中心 / 副标题画布内居中 / Ticker 遮罩用 mask-image

用户反馈第六轮漩涡"还在飘"、副标题没居中、Ticker 两侧白色遮罩不对。三条根源修复：

- **漩涡锁死的真正解法是放进 `.hero-canvas`**。上一版漩涡放在 `.hero`（100vw 宽度，随窗口变化），用 `top:50% left:50% + width:120%` 的百分比定位——**父元素尺寸一变，漩涡的视觉中心就跟着变**，这就是"屏幕越宽漩涡越往右下偏"的根因。解决：把 `<img class="hero-vortex">` 移入 `.hero-canvas` 内部，改用**绝对像素定位** `left:960px; top:503px`（1920×1006 画布的正中点），`width:1400px height:1400px` 固定像素。这样漩涡跟画布一起被同一个 `scale(100vw/1920)` 缩放，相对画布永远在中心，视觉上绝对不漂。**规律：只要是"必须跟主画布绝对对齐"的装饰元素，都要放画布里用像素定位，而不是放画布外用百分比。**
- **副标题居中用画布宽度 + text-align**：之前 `left:560px` 硬定位会让副标题永远贴在左边。正确做法是把它定位成 `left:0; top:470px; width:1920px; text-align:center`——让整行文本在整个 1920 画布里居中，无论文本长短都会自动对齐到画布水平中点 x=960。这是**画布绝对定位 + 内容居中**的标准组合技，比算每一个文本的左偏移靠谱得多。
- **Ticker 两侧遮罩用 `mask-image` 不用硬色块**。用户明确说"不要白色，要读取两侧背景色做遮罩"。硬涂浅蓝或白色渐变永远不可能"自动匹配背景"，因为背景可能是渐变、图片、漩涡叠加色。**正解是用 CSS `mask-image`**：`mask-image: linear-gradient(to right, transparent 0, #000 140px, #000 calc(100% - 140px), transparent 100%)`——这直接让 Ticker 自身的两端"变透明"，底层真实背景（无论是浅蓝渐变、漩涡、还是图片）会自然透出来，等于"读取两侧实际颜色做遮罩"。配合 `-webkit-mask-image` 做兼容。

经验新增：

- **子元素锁中心 = 父元素必须尺寸恒定**。如果父容器宽度跟着视口变，子元素用 `left:50%` 的"中心"也会跟着移动。要么父容器固定像素（画布模式 + scale），要么子元素改用像素绝对定位。绝不能"动态父容器 + 百分比子元素"。
- **两端淡出优先用 `mask-image`**：相比硬涂渐变色遮挡，`mask-image` 让元素自身透明化，底层真实背景自动透出，效果永远正确，不需要关心底层颜色。适用于 Logo Ticker、文字淡出、滚动条边缘淡化等所有"淡出到背景"的场景。
- **画布内居中的最佳实践**：`left:0; width:<画布宽>; text-align:center` 永远比"手算 left 偏移"靠谱。尤其是响应式 scale 画布里，手算的偏移会因为字体加载慢导致初始位置抖动。

## 第八轮迭代：漩涡"压扁 + 还在飘"终极修复

第七轮把漩涡移入画布后还是飘，排查发现两个根因：

1. **`width:1400px; height:1400px` 把 4:3 原图压扁成正方形**。漩涡原图是 `2502×1888`，强制正方形后图形的"光晕对称轴"位置错乱，旋转时就会看到"中心在动"——其实是图形形变在动。解法：查 `sips -g pixelWidth pixelHeight` 拿到真实比例，按比例给 `1600×1200`。
2. **`translate + rotate + scale` 合在同一个 transform 里会抖**。CSS transform 链从右往左执行：`scale rotate translate` 时 translate 最先做，但我写成 `translate scale rotate`——在 keyframe 里每帧都要重写完整链条，任何一帧漏掉/写错 translate 都会回到 (0,0)；更深的问题是 `rotate` 时整个坐标系会转，`translate(-50%,-50%)` 其实是在被旋转的坐标系里做平移——旋转到某些角度时视觉中心就会移动几十像素。

**终极正确解法：拆成两层 DOM**——
- 外层 `.hero-vortex-wrap`：只负责"把中心锁到画布 (960, 503)"，`position:absolute + left:960 + top:503 + transform: translate(-50%,-50%)`，动画永远不碰这层。
- 内层 `.hero-vortex` 图片：`width:100% height:100% + object-fit:contain` 保持比例，**animation 只在内层跑**，且 `@keyframes` 里**只有 `scale` 和 `rotate`，完全不写 `translate`**。这样旋转和缩放都发生在"已经居中"的坐标系里，translate 由外层锁死，rotate/scale 没有任何位移副作用。

经验新增：

- **"锁位置"和"做变换"必须拆成两层 DOM**：只要元素需要"固定在某个位置 + 自身做旋转/缩放动画"，就用外层 wrapper 负责定位 translate，内层负责 rotate/scale。**单层元素同时做这三种 transform，尤其是在 keyframe 里，极难不出 bug**。这个规律对任何需要"自转 Logo/Loading 圆圈/弹跳图标"都适用。
- **按比例给图片尺寸，先查原图**：任何用 PNG/JPG 做装饰的元素，写 width/height 之前先 `sips -g pixelWidth pixelHeight <file>` 查真实像素比。硬写正方形等于赌图片是正方形。
- **`animation: linear` vs `ease-in-out` 对"自转"的影响**：匀速自转一定要 `linear`，用 `ease-in-out` 会让漩涡在"半周期的中间"慢下来，看起来像"先快后慢又快"的诡异节奏。只有呼吸缩放（1→1.08→1）才适合 ease-in-out。这一版给 vortexLoop 改用了 `linear`。

## 第九轮迭代：Icon hover 发光从"发黑"改为"蓝+白双层辉光"

用户反馈 hover 时 icon 背景光"黑黑的"。排查：之前用的是单层 `drop-shadow(0 20px 35px rgba(15,40,100,.38))`——虽然 rgba 是深蓝，但 0.38 alpha + 较大模糊半径，在浅色 3D icon 下视觉上呈现为"深灰/发黑的投影"，观感差。

**正解：多层 drop-shadow 叠加做辉光，而不是单层深色阴影。**

```css
filter:
  drop-shadow(0 0 24px rgba(255,255,255,.85))      /* 内圈白色柔光，提亮边缘 */
  drop-shadow(0 18px 40px rgba(1,101,242,.55))     /* 外圈品牌蓝发光 */
  drop-shadow(0 4px 14px rgba(64,140,255,.45));    /* 补光层 */
```

经验新增：
- **hover 发光效果不用 `box-shadow`（会被透明 PNG 的矩形边界截断），用 `filter: drop-shadow` 叠多层**：第一层近距离白色柔光提亮 icon 本身，第二层外圈品牌色大半径辉光制造"被选中"感，第三层中距离淡色补光过渡。这三层组合出来的是"发光"而不是"投影"，绝不会发黑。
- **避免单层深色阴影做"高亮态"**：无论 rgba 颜色多偏蓝，alpha 大于 0.3 + 模糊半径大于 20px 在浅色背景下都倾向于被视觉识别为"灰黑阴影"。高亮/hover 态优先用亮色（白/品牌色）+ 高 alpha 的辉光层叠。
